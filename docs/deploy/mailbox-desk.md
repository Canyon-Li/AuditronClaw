# 邮箱事务台

定时只读近期邮箱 → 分类总结 → 待办落盘 → 摘要推送飞书的每日流水线，由心跳任务引擎驱动，与手动对话共用同一会话机制与审计流。

## 相关工具

网络能力是命名工具，不是匿名 socket：只有两个出站出口，各自绑定唯一目标域（域名白名单在代码里强制，LLM 的工具参数里没有 URL 字段）。

| 工具 | 作用 |
| --- | --- |
| `read_recent_emails` | 只读近期邮件（目标域 `imap.qq.com`） |
| `send_feishu_summary` | 推送文本摘要到飞书（目标域 `open.feishu.cn`） |
| `submit_mailbox_desk_report` | 事务台结构化提交：接收 agent 的分类结果，一次性完成日报渲染、待办落盘、飞书推送 |

> ⏱ 耐心提示：`read_recent_emails` 单次调用约需 **120 秒**（IMAP 拉取较慢）。

凭据只存在宿主机 `.env`——工具参数、返回值、LLM 上下文、审计日志四个执行面里永远不出现授权码与 webhook URL。未配置时网络工具返回结构化错误（不碰网络），不影响其他功能。

## 启动教程

### 1. 配置凭据

复制 `.env.example` 为 `.env`（已 gitignore），补三项：

| 环境变量 | 哪里拿 | 说明 |
| --- | --- | --- |
| `MAIL_ACCOUNT` | 你的 QQ 邮箱地址 | 如 `someone@qq.com` |
| `MAIL_IMAP_PASSWORD` | QQ 邮箱网页版 → 设置 → 账户 → 开启 IMAP/SMTP 服务 → 生成授权码 | **不是登录密码**，是 16 位授权码 |
| `FEISHU_WEBHOOK_URL` | 飞书群 → 设置 → 群机器人 → 添加自定义机器人（免签） | 完整 webhook URL |

### 2. 手动跑一轮

在会话里直接说（`auditronclaw run` 后任意输入）：

> 跑一轮邮箱事务台，共两步：
> 1. 调用 read_recent_emails(hours=24, max_emails=10) 读取近期 24 小时邮件，只调用一次。
> 2. 把分类结果作为参数调用 submit_mailbox_desk_report 一次性提交——分类规则
>    在该工具的说明里。日报排版、待办落盘、飞书推送都由该工具完成，不要再调
>    send_feishu_summary 或 schedule_task。

管线只有两次工具调用：agent 只负责分类判断（填结构化字段），日报渲染、待办落盘、推送全部由 `submit_mailbox_desk_report` 代码完成——格式、顺序、副作用不依赖模型自觉。

第一步读信约需 2 分钟，期间 agent 无回复属正常，等回执即可，不必重发指令。

### 3. 建每日循环任务

验收没问题后，在会话里说：

> 以后每天 08:00 跑一轮邮箱事务台，repeat 设为 daily。任务描述就用上面那段
> 两步管线指令原文，每天到点按它执行。

之后每天到点，心跳引擎把指令塞进会话队列，agent 照常执行。`auditronclaw run` 挂着即可，到期那轮会自己开始；想先演练，可临时建一条两分钟后到期的同款任务观察触发。

### 4. 停用（删任务即停）

在会话里说"删掉邮箱事务台的循环任务"（id 可先问 `list_scheduled_tasks`）。彻底停用网络能力：从 `.env` 删掉三项凭据、清掉 `tasks.json` 里的事务台任务即可，没有任何隐藏状态。

## 可选

- **域名白名单扩展**：默认名单开箱即用；`AUDITRONCLAW_ALLOWED_DOMAINS` 可追加域（逗号分隔），扩展留审计事件。换邮箱服务商或推送通道不是改 `.env` 一行的事——新域要先写进工具绑定（代码常量），环境变量只放行、不指路。
- **推送失败的行为（预期）**：断网 / webhook 失效时待办仍落盘（先落待办、后推送，代码强制）；回执如实报告，审计留"飞书推送失败"事件（文案不含 webhook URL）；失败不留状态，下一轮正常。
